
# CCNA 200-301 — DHCP Configuration in Cisco Packet Tracer

## Lab 1: Configure a Cisco Router as a DHCP Server

### 1. Lab Objective

Build a Treasury department network where computers automatically receive IP addresses from a Cisco router.

**We will configure:**
- Cisco Router as DHCP Server.
- Switch to connect computers.
- Two PCs as DHCP Clients.
- Automatic IP address assignment.
- Verification and troubleshooting.

### 2. Network Topology

**Required Devices:**

| Device | Quantity | Role |
|---|---:|---|
| Cisco Router (1941/2911) | 1 | DHCP Server and Gateway |
| Cisco Switch (2960) | 1 | Connects LAN devices |
| PC-PT | 2 | DHCP Clients |

**Network Diagram:**

```text
                  Router R1
               DHCP Server
              192.168.10.1
                    |
                    |
                GigabitEthernet
                    |
                Switch SW1
                 /       \
                /         \
              PC0         PC1
           DHCP Client  DHCP Client
```

**Cable Connections:**

| From | To | Cable |
|---|---|---|
| Router G0/0 | Switch G0/1 | Copper Straight-Through |
| Switch F0/1 | PC0 F0 | Copper Straight-Through |
| Switch F0/2 | PC1 F0 | Copper Straight-Through |

### 3. IP Address Planning

Our Treasury network:

`192.168.10.0/24`

| Network Setting | Value |
|---|---|
| Network Address | 192.168.10.0 |
| Subnet Mask | 255.255.255.0 |
| Default Gateway | 192.168.10.1 |
| DHCP Starting Address | 192.168.10.21 |
| DHCP Ending Address | 192.168.10.254 |
| DNS Server | 8.8.8.8 |
| Broadcast Address | 192.168.10.255 |

**IP Reservation:**

We will exclude addresses `.1 – .20` from DHCP.

| IP Range | Purpose |
|---|---|
| 192.168.10.1 | Router / Gateway |
| 192.168.10.2 – .20 | Reserved for servers and infrastructure |
| 192.168.10.21 – .254 | DHCP Client Pool |

### 4. Configure the Cisco Router

Open Router R1 → CLI.

Enter the following commands:

**Step 1: Enter Privileged EXEC Mode**

```cisco
enable
```

**Step 2: Enter Global Configuration Mode**

```cisco
configure terminal
```

**Step 3: Set Router Hostname**

```cisco
hostname R1
```

**Step 4: Configure Router Interface**

```cisco
interface gigabitEthernet 0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit
```

**Explanation:**
- `interface gigabitEthernet 0/0` → Selects the router interface.
- `ip address` → Assigns the gateway IP.
- `no shutdown` → Activates the interface.
- `exit` → Returns to global configuration mode.

*Note: Check your router's actual interface name using `show ip interface brief`. Some models use G0/0/0 instead of G0/0.*

### 5. Exclude Reserved IP Addresses

We don't want DHCP to assign the gateway or reserved infrastructure addresses to ordinary computers.

**Command:**

```cisco
ip dhcp excluded-address 192.168.10.1 192.168.10.20
```

**Meaning:** The router must not assign IP addresses from `.1` through `.20` through this DHCP service.

### 6. Create the DHCP Pool

Now create a DHCP pool named TREASURY.

```cisco
ip dhcp pool TREASURY
```

**Configure Network Address:**

```cisco
network 192.168.10.0 255.255.255.0
```

**Configure Default Gateway:**

```cisco
default-router 192.168.10.1
```

**Configure DNS Server:**

```cisco
dns-server 8.8.8.8
```

**Configure Domain Name:**

```cisco
domain-name treasury.bank.local
```

**Configure Lease Time:**

```cisco
lease 1
```

**Exit Configuration:**

```cisco
exit
end
```

**Complete DHCP Configuration:**

```cisco
enable
configure terminal

hostname R1

interface gigabitEthernet 0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit

ip dhcp excluded-address 192.168.10.1 192.168.10.20

ip dhcp pool TREASURY
network 192.168.10.0 255.255.255.0
default-router 192.168.10.1
dns-server 8.8.8.8
domain-name treasury.bank.local
lease 1
exit

end
write memory
```

**Important:** Cisco IOS DHCP service is enabled by default. If it has previously been disabled with `no service dhcp`, enable it using `service dhcp`.

### 7. Configure PCs to Receive IP Automatically

Now configure PC0 and PC1.

**For PC0:**
1. Click PC0.
2. Open Desktop.
3. Open IP Configuration.
4. Select DHCP instead of Static.

**For PC1:**
1. Click PC1.
2. Open Desktop.
3. Open IP Configuration.
4. Select DHCP.

Both PCs should automatically receive network settings.

**Expected Results:**

| Setting | PC0 | PC1 |
|---|---|---|
| IP Address | 192.168.10.21 | 192.168.10.22 |
| Subnet Mask | 255.255.255.0 | 255.255.255.0 |
| Default Gateway | 192.168.10.1 | 192.168.10.1 |
| DNS Server | 8.8.8.8 | 8.8.8.8 |

*Note: These are expected example assignments for a fresh pool. Actual assignment order depends on existing leases and available addresses.*

### 8. Verify DHCP Configuration Using Cisco IOS Commands

Go to Router R1 → CLI.

**Command 1: Check Interface Status**

```cisco
show ip interface brief
```

Expected:

- G0/0 IP = 192.168.10.1
- Status = up
- Protocol = up

**Command 2: Check DHCP Pool**

```cisco
show ip dhcp pool
```

Shows:
- Pool name.
- Total addresses.
- Leased addresses.
- Available addresses.

**Command 3: Check DHCP Bindings**

```cisco
show ip dhcp binding
```

Shows:
- Assigned IP addresses.
- Client identifiers.
- Lease expiration information.

**Command 4: Check DHCP Server Statistics**

```cisco
show ip dhcp server statistics
```

Shows DHCP message statistics, such as Discover, Offer, Request and ACK counts. Availability of this command may vary in Packet Tracer.

**Command 5: Check Running Configuration**

```cisco
show running-config
```

Verify:
- Interface IP address.
- Excluded addresses.
- DHCP pool.
- Network statement.
- Default gateway.
- DNS server.

### 9. Test Network Connectivity

On PC0 → Desktop → Command Prompt.

**Check IP Configuration:**

```text
ipconfig /all
```

**Ping Default Gateway:**

```text
ping 192.168.10.1
```

**Ping PC1:**

```text
ping 192.168.10.22
```

Use PC1's actual assigned IP if it differs.

**Expected Result:** Successful ping replies indicate that the PCs can communicate with the gateway and each other.

*The first ping may time out while ARP resolves the destination MAC address. Try again.*

**DNS Note:** We assigned 8.8.8.8 as the DNS server, but name resolution will work only if an appropriate DNS service and upstream network connectivity are available.

### 10. Troubleshooting Common DHCP Problems

| Problem | Possible Cause | Solution |
|---|---|---|
| PC receives no IP | DHCP pool missing | Check `show ip dhcp pool` |
| PC receives 169.254.x.x | DHCP request failed | Check DHCP server and connectivity |
| Interface is down | Router interface shutdown | Use `no shutdown` |
| Wrong Gateway | Incorrect DHCP option | Check `default-router` |
| Wrong Subnet Mask | Incorrect network statement | Check `network` command |
| Duplicate IP | Address conflict | Check exclusions and static assignments |
| No DHCP binding | Client request not reaching server | Check cables, VLAN and DHCP messages |
| Remote VLAN gets no IP | Missing DHCP relay | Configure `ip helper-address` |

### 11. Observe DORA in Packet Tracer Simulation Mode

This exercise helps you see the actual DHCP message exchange.

**Steps:**

1. Change Packet Tracer from Realtime to Simulation mode.
2. Open Edit Filters.
3. Select DHCP.
4. On PC0, open Desktop → IP Configuration.
5. Select Static and then select DHCP again to trigger a new request.
6. Click Capture/Forward to observe each packet.

**Observe the Four Messages:**

| Order | DHCP Message | Direction |
|---|---|---|
| 1 | Discover | Client → Server |
| 2 | Offer | Server → Client |
| 3 | Request | Client → Server |
| 4 | ACK | Server → Client |

**Remember:** DORA = Discover → Offer → Request → Acknowledgment.
