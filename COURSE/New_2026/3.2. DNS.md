## 1. What is DNS?

**DNS = Domain Name System.**

DNS is a network service that translates human-readable domain names into IP addresses.

**Simple Explanation:** Humans remember website names, but computers use IP addresses for network communication. DNS translates the website name into its corresponding IP address.

### Real-Life Analogy: Mobile Phone Contacts

Imagine you want to call a bank employee.

You don't remember their phone number, but you remember their name.

You search the name in your mobile contacts, and your phone shows the number.

| Real-Life Example | DNS Concept |
|---|---|
| Employee Name | Domain Name |
| Phone Contact List | DNS Database |
| Employee Phone Number | IP Address |
| Searching Contact | DNS Query |
| Finding Phone Number | DNS Resolution |

**Memory Trick:**
- DHCP = Gives IP Address.
- DNS = Finds IP Address using a Name.
- NAT = Translates IP Addresses.

### Example

You type into your browser:

`www.example.com`

Your computer needs an IP address to communicate with the destination server.

For illustration, imagine DNS returns:

`203.0.113.20`

Your computer can then use that destination IP to establish a network connection.

*Note: 203.0.113.20 is a documentation-only example IP address, not a real website server.*

## 2. Why Do We Need DNS?

Imagine a bank employee needs to access five internal systems:

- Treasury banking system.
- Remittance system.
- Trade finance system.
- SWIFT support portal.
- Email server.

Without DNS, employees may need to remember IP addresses.

With DNS, they can use memorable names.

| Without DNS | With DNS |
|---|---|
| Remember IP addresses | Remember domain names |
| Difficult for users | Easy for users |
| Manual IP reference | Name resolution |
| IP changes require updating references | DNS records can be updated centrally |

**Important:** DNS makes network resources easier to locate. It does not assign IP addresses or route packets.

**Memory Trick:** DNS = Internet Phonebook.

## 3. How Does DNS Work? — Step by Step

This is one of the most important concepts in DNS.

Imagine a Treasury employee wants to access:

`portal.bank.example`

How does the computer find its IP address?

### Step 1: User Enters a Domain Name

The employee types:

`portal.bank.example`

The computer needs to find the corresponding IP address.

### Step 2: Check Local DNS Information

Before contacting an external DNS server, the computer or its resolver may check:

1. Browser DNS cache.
2. Operating System DNS cache.
3. Local Hosts File.

If a valid matching entry exists, it may use that information without making a new external DNS query.

### Step 3: Contact the Recursive DNS Resolver

If no suitable local result exists, the computer contacts its configured DNS resolver.

Usually, the DNS server address is received through DHCP.

**Example:**

| Setting | Value |
|---|---|
| Computer IP | 192.168.10.100 |
| Default Gateway | 192.168.10.1 |
| DNS Server | 192.168.10.2 |
| Requested Domain | portal.bank.example |

The computer asks:

"What is the IP address of portal.bank.example?"

This is normally a **recursive DNS query**.

### Step 4: Recursive Resolver Checks Its Cache

The DNS resolver checks whether it already knows the answer.

- If the answer exists and its TTL has not expired, it returns the cached answer.
- If not, it starts resolving the name using other DNS servers.

### Step 5: Contact Root DNS Server

If the resolver needs to resolve the domain from scratch, it starts at the DNS root hierarchy.

The Root DNS server knows where to find the relevant Top-Level Domain (TLD) servers.

It provides a referral to the next level.

### Step 6: Contact TLD DNS Server

The resolver contacts the appropriate TLD server.

Examples of TLDs:

- `.com`
- `.org`
- `.net`
- `.bd`
- `.edu`

For `www.example.com`, the TLD is `.com`.

The TLD server provides a referral to the authoritative DNS servers for the domain.

### Step 7: Contact Authoritative DNS Server

The authoritative DNS server stores the original DNS records for its zone.

It checks its records and returns the requested answer.

**Illustrative DNS Record:**

```text
www.example.com.   A   203.0.113.20
```

The resolver now knows the destination IP address.

### Step 8: Return the IP Address to the Computer

The recursive resolver sends the result to the employee's computer.

The computer can now use the destination IP address to establish the connection.

### Complete DNS Resolution Process

```text
       Employee's Computer
                |
                | Requests Domain Name
                v
          Local DNS Cache
                |
                | Cache Miss
                v
       Recursive DNS Resolver
                |
                | Checks Its Cache
                v
          Root DNS Server
                |
                | Referral to TLD
                v
           TLD DNS Server
                |
                | Referral to Authoritative DNS
                v
      Authoritative DNS Server
                |
                | Returns DNS Record
                v
       Recursive DNS Resolver
                |
                | Returns IP Address
                v
         Employee's Computer
                |
                v
       Connects to Destination
```

**Remember:**

Computer → Resolver → Root → TLD → Authoritative → IP Address.

*This is the simplified full lookup path. Actual resolution may stop earlier if a cache or forwarding resolver already has the answer. Root and TLD servers normally provide referrals, not the final website IP.*

## 4. Recursive vs Iterative DNS Queries

**Very Important for CCNA**

There are two important types of DNS queries.

### A. Recursive DNS Query

**Meaning:** The DNS server must find the final answer for the client or return an error.

Simple explanation:

The client asks the DNS resolver:

"Please find the IP address of portal.bank.example for me."

The resolver takes responsibility for finding the answer.

The client does not need to contact Root, TLD and Authoritative DNS servers separately.

**Analogy:** You ask a travel agent to arrange your entire journey. The agent contacts airlines and hotels and gives you the completed arrangement.

```text
          DNS CLIENT
              |
              | Recursive Query
              v
       RECURSIVE RESOLVER
              |
              | Finds Final Answer
              v
          IP ADDRESS
```

### B. Iterative DNS Query

**Meaning:** The DNS server provides the best information it has, or refers the requester to another DNS server.

Example:

1. Ask Root DNS → Get TLD referral.
2. Ask TLD DNS → Get Authoritative DNS referral.
3. Ask Authoritative DNS → Get final IP address.

**Analogy:** You ask someone for a bank address. They say, "Ask the security desk." Security says, "Go to the Treasury floor." You follow the directions until you reach your destination.

```text
       RECURSIVE RESOLVER
                |
                v
           ROOT DNS
                |
                | Referral to TLD
                v
            TLD DNS
                |
                | Referral to Authoritative DNS
                v
       AUTHORITATIVE DNS
                |
                | Final DNS Record
                v
            IP ADDRESS
```

### C. Difference Between Recursive and Iterative

| Recursive | Iterative |
|---|---|
| Server finds the final answer | Server provides best answer/referral |
| Client depends on resolver | Requester follows referrals |
| More work for recursive resolver | Resolution work is distributed |
| Common: Client → Resolver | Common: Resolver → DNS hierarchy |

**Important CCNA Point:**

In normal Internet DNS resolution:

- Client → Recursive DNS Resolver = Recursive Query.
- Recursive Resolver → Root/TLD/Authoritative Servers = Usually Iterative Queries.

These two processes work together.

### Three Important DNS Flags

| Flag | Full Form | Meaning |
|---|---|---|
| RD | Recursion Desired | Client requests recursive resolution |
| RA | Recursion Available | Server indicates it offers recursion |
| AA | Authoritative Answer | Response is authoritative for the queried name |

**Remember:**
- RD = Client's request for recursion.
- RA = Server's recursion availability.
- AA = Authoritative response.

## 5. DNS Caching and TTL

**DNS Cache:** Temporary storage of previously learned DNS information.

### Why Do We Need DNS Caching?

Imagine 100 bank employees access the same banking website.

Without caching, the same DNS lookup may repeatedly travel through the DNS hierarchy.

With caching, the resolver can reuse a valid previous answer.

### How DNS Caching Works

```text
        FIRST REQUEST
              |
              v
          DNS Resolver
              |
              v
       No Answer in Cache
              |
              v
         DNS Lookup
              |
              v
     Authoritative DNS Server
              |
              v
        Returns Answer
              |
              v
        Stores in Cache
              |
              v
       SECOND REQUEST
              |
              v
       Uses Cached Answer
```

### What is TTL?

**TTL = Time To Live.**

TTL determines how long a DNS record can remain in a cache.

**Example:**

```text
portal.bank.example
Type: A
IP: 203.0.113.20
TTL: 3600 seconds
```

3600 seconds = 1 hour.

| TTL | Meaning |
|---|---|
| 60 seconds | Cache for up to 1 minute |
| 300 seconds | Cache for up to 5 minutes |
| 3600 seconds | Cache for up to 1 hour |
| 86400 seconds | Cache for up to 24 hours |

After TTL expires, the cached record must not be reused as a fresh valid answer; the resolver needs to obtain current information.

### Why is TTL Important?

- Reduces DNS traffic.
- Improves response speed.
- Reduces repeated queries.
- Controls how quickly changes can become visible through caches.

### Positive and Negative Caching

**Positive Caching:** Stores a successful DNS answer.

**Negative Caching:** Stores information that a requested name or record does not exist.

Example:

You search for:

`unknown.bank.example`

The DNS server responds that the name does not exist (NXDOMAIN).

A resolver may cache that negative response for its negative TTL, preventing repeated unnecessary queries.

**Memory Trick:** TTL = How Long DNS Remembers an Answer.

## 6. Important DNS Record Types

**Memorize These for CCNA**

DNS records are stored in DNS databases and provide different types of information.

### DNS Record Summary Table

| Record | Full Name / Purpose | Example |
|---|---|---|
| A | Maps name to IPv4 address | 192.168.10.10 |
| AAAA | Maps name to IPv6 address | IPv6 address |
| CNAME | Alias of another domain name | www → server.example.com |
| MX | Mail server information | mail.example.com |
| NS | Authoritative name server | ns1.example.com |
| PTR | Reverse lookup: IP to name | IP → hostname |
| SOA | Start of Authority; zone information | Serial, refresh, retry |
| TXT | Text information | SPF, DKIM, domain verification |
| SRV | Service location and port | Service host and port |

### Understand the Most Important Records

#### 1. A Record — IPv4

Connects a domain name to an IPv4 address.

```text
portal.bank.example → 192.168.10.10
```

**Memory:** A = IPv4 Address.

#### 2. AAAA Record — IPv6

Connects a domain name to an IPv6 address.

**Memory:** AAAA = IPv6 Address.

#### 3. CNAME Record — Alias

Points one domain name to another canonical domain name.

Example:

```text
www.bank.example
       |
       v
portal.bank.example
       |
       v
192.168.10.10
```

**Memory:** CNAME = Another Name.

#### 4. MX Record — Mail Exchange

Identifies which mail server receives email for a domain.

Example:

```text
bank.example → mail.bank.example
```

MX records have preference values; a lower preference number is preferred over a higher one.

**Memory:** MX = Mail Server.

#### 5. NS Record — Name Server

Identifies the authoritative DNS servers for a domain or zone.

**Memory:** NS = Name Server.

#### 6. PTR Record — Reverse DNS

Maps an IP address back to a domain name.

Normal DNS:

`Name → IP`

Reverse DNS:

`IP → Name`

**Memory:** PTR = Reverse Lookup.

#### 7. SOA Record — Start of Authority

Contains important administrative information about a DNS zone, including:
- Primary authoritative server.
- Responsible administrator's mailbox.
- Serial number.
- Refresh and retry timers.
- Expiry information.

**Memory:** SOA = Zone Information.

#### 8. TXT Record — Text

Stores text information associated with a domain.

Common uses:
- SPF email authentication.
- DKIM public-key information.
- Domain ownership verification.

**Memory:** TXT = Text Information.

#### 9. SRV Record — Service Location

Identifies the hostname and port of a particular service.

**Memory:** SRV = Service Location.

### Quick Record Memory Trick

- A = IPv4
- AAAA = IPv6
- CNAME = Alias
- MX = Mail
- NS = Name Server
- PTR = Reverse Lookup
- SOA = Zone Authority
- TXT = Text
- SRV = Service Location

## 7. DNS Ports — UDP 53 vs TCP 53

**Important CCNA Exam Topic**

DNS uses two transport protocols:

- UDP Port 53.
- TCP Port 53.

### UDP 53 vs TCP 53

| UDP Port 53 | TCP Port 53 |
|---|---|
| Used for most ordinary DNS queries | Used for zone transfers |
| Lower overhead | Reliable connection |
| Common for typical small queries | Handles larger DNS responses |
| No connection establishment | Connection-oriented |

### A. Why UDP 53?

UDP is commonly used for normal DNS queries because it has lower overhead.

Example:

Your Treasury computer asks:

"What is the IP address of portal.bank.example?"

It sends a DNS query to the DNS server using UDP port 53.

### B. Why TCP 53?

TCP is used for:

1. **Zone Transfers:** Transferring DNS zone information between DNS servers (AXFR/IXFR).
2. **Large Responses:** When a DNS response is too large for the UDP response and is truncated, the client can retry over TCP.
3. **Reliable Transfer:** TCP provides reliable, ordered delivery.

Modern DNS implementations must support both UDP and TCP. TCP is not limited to being a fallback; it can also be selected directly.

### DNS Communication

| Communication | Protocol | Destination Port |
|---|---|---:|
| PC → DNS Server | UDP | 53 |
| PC → DNS Server | TCP | 53 |
| DNS Server → PC | UDP/TCP | Client's source port |

**Remember:** DNS Server = Port 53, regardless of whether DNS uses UDP or TCP.

### Extra Knowledge: Encrypted DNS

| Technology | Common Port |
|---|---:|
| Traditional DNS | UDP/TCP 53 |
| DNS over TLS (DoT) | TCP 853 |
| DNS over HTTPS (DoH) | HTTPS 443 |
| DNS over QUIC (DoQ) | UDP 853 |

For basic CCNA revision, prioritize UDP 53 and TCP 53.

## 8. DNS Configuration and Verification

Now connect theory with practical networking.

### A. Configure DNS on a Cisco Router

Suppose your bank has an internal DNS server:

`192.168.10.2`

Configure the Cisco router to use this DNS server:

```cisco
enable
configure terminal
ip name-server 192.168.10.2
ip domain lookup
end
```

### Explanation

| Command | Purpose |
|---|---|
| `ip name-server` | Specifies DNS server |
| `ip domain lookup` | Enables DNS name resolution |
| `show hosts` | Displays DNS cache and configured name servers |

**Important:** These commands configure DNS resolution on the Cisco router itself. They do not automatically configure every connected PC to use this DNS server.

DHCP can provide the DNS server address to PCs using:

```cisco
ip dhcp pool TREASURY
dns-server 192.168.10.2
```

### B. Windows DNS Verification Commands

| Command | Purpose |
|---|---|
| `ipconfig /all` | Shows configured DNS server |
| `nslookup example.com` | Queries DNS |
| `nslookup -type=MX example.com` | Checks MX records |
| `ipconfig /displaydns` | Displays Windows DNS cache |
| `ipconfig /flushdns` | Clears Windows DNS cache |
| `ping hostname` | Tests name resolution and connectivity |

### Example: nslookup

```text
nslookup portal.bank.example
```

Illustrative output:

```text
Server:  192.168.10.2
Address: 192.168.10.2

Name:    portal.bank.example
Address: 203.0.113.20
```

**Meaning:**
- DNS Server = 192.168.10.2
- Requested Domain = portal.bank.example
- Resolved IP = 203.0.113.20

*The example IP is reserved for documentation.*

## 9. DNS Troubleshooting — Common Problems

Imagine a Treasury employee reports:

"I cannot open the banking website."

A network administrator should investigate:

| Problem | Possible Cause | Solution |
|---|---|---|
| Website name not resolving | DNS server unavailable | Check DNS server connectivity |
| Wrong IP returned | Incorrect DNS record or stale cache | Check DNS records and TTL |
| Domain returns NXDOMAIN | Name does not exist | Check domain spelling and records |
| DNS query times out | Firewall or network issue | Check UDP/TCP 53 connectivity |
| IP works but hostname fails | DNS resolution issue | Check configured DNS server |
| External names work but internal names fail | Internal DNS zone issue | Check internal DNS records |
| Website fails after IP change | Cached old DNS record | Check TTL and clear relevant cache |

### Most Important Troubleshooting Scenario

**Scenario:** A computer can successfully ping `192.168.10.1`, but cannot access a website using its domain name.

**What should you check?**

1. Check the computer's DNS server using `ipconfig /all`.
2. Test name resolution using `nslookup`.
3. Check whether the DNS server is reachable.
4. Verify DNS records.
5. Check firewall rules for UDP/TCP port 53.

**Important CCNA Concept:**
- Ping IP works, hostname fails → Suspect DNS.
- Ping gateway fails → Investigate LAN, IP configuration or connectivity first.

## 10. DHCP vs DNS — How Are They Connected?

You studied DHCP in the previous lesson. Now connect both technologies.

Imagine a new Treasury PC joins the bank network.

### DHCP + DNS Working Together

```text
          New Treasury PC
                 |
                 v
             DHCP Server
                 |
                 | Provides:
                 | IP Address
                 | Subnet Mask
                 | Gateway
                 | DNS Server
                 |
                 v
              DNS Server
                 |
                 | Resolves Domain Name
                 | into IP Address
                 |
                 v
          Destination Server
```

### Difference at a Glance

| DHCP | DNS |
|---|---|
| Assigns IP configuration | Resolves domain names |
| Uses UDP 67/68 | Uses UDP/TCP 53 |
| Uses DORA | Uses DNS queries and responses |
| Provides DNS server address | Resolves names using DNS records |

**Golden Memory Trick:**

DHCP tells your computer which DNS server to use.

DNS tells your computer which IP address belongs to a domain name.

## 11. Common CCNA Exam Traps

1. DNS does not assign IP addresses. DHCP does.
2. DNS does not translate IP addresses into MAC addresses. ARP performs IPv4 address-to-MAC resolution on the local link.
3. Root DNS servers do not normally provide the final website IP.
4. DNS uses both UDP and TCP port 53.
5. CNAME is an alias, not an IP address.
6. A = IPv4, AAAA = IPv6.
7. PTR performs reverse DNS lookup.
8. TTL controls how long a DNS record can remain in a cache.
9. Recursive query = Resolver finds the final answer.
10. Iterative query = Server provides the best available answer or a referral.
