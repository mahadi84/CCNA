১. Core Network Monitoring

বাস্তব সময়ে নেটওয়ার্ক পর্যবেক্ষণ

* Core Switch ও Router সচল আছে কি না দেখা।
* CPU, memory, interface utilization ও packet errors পর্যবেক্ষণ করা।
* Fiber uplink এবং গুরুত্বপূর্ণ network path পরীক্ষা করা।
* NMS, SNMP, Syslog ও monitoring alerts বিশ্লেষণ করা।

উপমা: মহাসড়কের ট্রাফিক কন্ট্রোল রুম থেকে যান চলাচল, দুর্ঘটনা ও রাস্তার অবস্থা পর্যবেক্ষণ করা।

২. Redundancy ও High Availability নিশ্চিত করা

* গুরুত্বপূর্ণ Core Switch ও Router-এর বিকল্প ব্যবস্থা যাচাই করা।
* Redundant fiber links ও power supply-এর অবস্থা পরীক্ষা করা।
* Routing failover সঠিকভাবে কাজ করছে কি না নিশ্চিত করা।
* অনুমোদিত maintenance window-তে failover test করা।

উপমা: একটি মহাসড়ক বন্ধ হয়ে গেলে বিকল্প মহাসড়ক দিয়ে যান চলাচল চালু রাখা।
কেন জরুরি? Core Network-এ বড় ধরনের ব্যর্থতা হলে একসঙ্গে অনেক বিভাগ, সার্ভার বা শাখার যোগাযোগ বিঘ্নিত হতে পারে।

৩. Routing ও Backbone Connectivity পরিচালনা

* Core routing table ও routing adjacency পরীক্ষা করা।
* OSPF বা BGP-এর মতো ব্যবহৃত routing protocol-এর অবস্থা পর্যবেক্ষণ করা।
* Distribution Layer ও Data Center-এর মধ্যে সঠিক route আছে কি না যাচাই করা।
* অপ্রত্যাশিত route change বা routing loop শনাক্ত করা।

উপমা: কোন শহর থেকে কোন শহরে যাওয়ার মহাসড়ক খোলা আছে এবং কোন রুট দিয়ে যান চলাচল হবে, তা নিশ্চিত করা।

৪. Network Performance ও Capacity Management

* Bandwidth utilization এবং congestion পর্যবেক্ষণ করা।
* Latency, packet loss ও interface errors বিশ্লেষণ করা।
* কোন লিংক ভবিষ্যতে অতিরিক্ত ব্যস্ত হয়ে পড়তে পারে, তা শনাক্ত করা।
* নতুন bandwidth বা hardware capacity-এর প্রয়োজন নির্ধারণ করা।

উপমা: প্রতিদিন মহাসড়কে গাড়ির সংখ্যা বাড়ছে কি না দেখে ভবিষ্যতে আরও লেন তৈরি করার পরিকল্পনা করা।

৫. Critical Network Incident সমাধান

ধরুন, ব্যাংকের Head Office, Data Center এবং কয়েকটি শাখায় একই সময়ে যোগাযোগের সমস্যা দেখা দিয়েছে।

* Core uplink ও interface status পরীক্ষা করবেন।
* Routing adjacency, route changes এবং packet loss যাচাই করবেন।
* Fiber, power, hardware বা configuration সমস্যা শনাক্ত করবেন।
* প্রয়োজনে Distribution, Data Center, WAN ও ISP টিমের সঙ্গে সমন্বয় করবেন।
* সমাধানের পর service recovery নিশ্চিত করে incident report তৈরি করবেন।

উপমা: একটি গুরুত্বপূর্ণ মহাসড়ক বন্ধ হয়ে গেলে কারণ শনাক্ত করে দ্রুত বিকল্প পথ চালু করা।

৬. Change Management ও Documentation

* Core Network configuration-এর backup রাখা।
* অনুমোদিত পরিবর্তনের impact assessment করা।
* Maintenance window, rollback plan ও recovery procedure প্রস্তুত করা।
* Network topology, IP addressing এবং routing documentation হালনাগাদ রাখা।

উপমা: মহাসড়কে মেরামত শুরু করার আগে অনুমতি নেওয়া, বিকল্প রাস্তা তৈরি করা এবং জরুরি পরিকল্পনা রাখা।

### ৩. একজন Core Network Officer-এর একটি বাস্তব কর্মদিবস

ধরা যাক, আপনি সকাল ৯টা থেকে বিকেল ৫টা পর্যন্ত একটি ব্যাংকের Core Network পরিচালনা করেন।

| সময়                | আপনার কাজ                                                               |
| ------------------- | ----------------------------------------------------------------------- |
| সকাল ৯টা–১০টা       | Network dashboard, overnight alerts, core links ও device health পরীক্ষা |
| সকাল ১০টা–১১টা      | Routing table, redundancy ও performance review                          |
| সকাল ১১টা–দুপুর ১টা | Network incident troubleshooting এবং সংশ্লিষ্ট টিমের সঙ্গে সমন্বয়      |
| দুপুর ১টা–২টা       | বিরতি অথবা জরুরি incident অনুযায়ী কাজ                                  |
| দুপুর ২টা–৩টা       | Approved configuration change, capacity planning বা hardware review     |
| বিকেল ৩টা–৪টা       | Security, Data Center ও WAN টিমের সঙ্গে সমস্যা সমাধান                   |
| বিকেল ৪টা–৫টা       | Documentation, incident report এবং পরবর্তী maintenance plan             |


এটি একটি নমুনা রুটিন। বাস্তবে জরুরি ঘটনা, maintenance এবং ব্যাংকের শিফট অনুযায়ী কাজের সময় বদলাতে পারে।

### ৪. একটি বাস্তব পরিস্থিতি: Core Link Failure

ধরুন, সকাল ১০টায় আপনার monitoring system alert দিল:

“Core Switch A থেকে Data Center-এর primary link down।”
এখন একজন Core Network Officer হিসেবে আপনি কী করবেন?

ধাপ ১: Alert যাচাই
Monitoring dashboard ও switch interface status দেখে নিশ্চিত হবেন লিংকটি সত্যিই down কি না।

ধাপ ২: বিকল্প পথ সচল কি না দেখুন
Redundant link দিয়ে traffic চলেছে কি না এবং routing convergence সঠিকভাবে হয়েছে কি না যাচাই করবেন।

ধাপ ৩: মূল কারণ খুঁজুন
Interface errors, optic module, fiber connection, remote device এবং সংশ্লিষ্ট logs পরীক্ষা করবেন।

ধাপ ৪: সমাধান ও যাচাই
অনুমোদিত পদ্ধতিতে লিংক মেরামত করবেন বা সংশ্লিষ্ট টিমকে যুক্ত করবেন। তারপর packet loss, latency ও application connectivity পরীক্ষা করবেন।

ধাপ ৫: Incident report
কতক্ষণ সমস্যা ছিল, কী কারণে হয়েছিল, কীভাবে সমাধান হয়েছে এবং ভবিষ্যতে কীভাবে প্রতিরোধ করা যায়—তা নথিভুক্ত করবেন।

সিনিয়র পর্যায়ের গুরুত্বপূর্ণ দক্ষতা: শুধু লিংক আবার চালু করা যথেষ্ট নয়। কেন ব্যর্থ হয়েছে এবং একই ঘটনা যেন আবার না ঘটে, সেটিও বিশ্লেষণ করতে হবে।

### ৫. Core Layer-এ কোন প্রযুক্তি জানা জরুরি?

| প্রযুক্তি                | কেন প্রয়োজন                                                         |
| ------------------------ | -------------------------------------------------------------------- |
| VLAN ও Layer 3 Switching | Distribution Layer-এর সঙ্গে সংযোগ বোঝার জন্য                         |
| OSPF / BGP               | Routing ও route failure বিশ্লেষণের জন্য                              |
| STP / LACP               | প্রযোজ্য ক্ষেত্রে Layer 2 loop prevention ও link aggregation-এর জন্য |
| HSRP / VRRP              | ব্যবহৃত হলে gateway redundancy বোঝার জন্য                            |
| SNMP / Syslog / NMS      | Monitoring ও troubleshooting-এর জন্য                                 |
| Fiber optics / SFP       | Backbone link ও optic-related fault শনাক্ত করার জন্য                 |
| QoS                      | গুরুত্বপূর্ণ traffic-এর performance নিশ্চিত করতে                     |
| Network security         | Routing protection, management access ও নিরাপদ configuration-এর জন্য |

সব নেটওয়ার্কে সব প্রযুক্তি ব্যবহার করা হয় না। আপনার ব্যাংকের vendor, topology ও design অনুযায়ী প্রয়োজনীয় প্রযুক্তি শিখতে হবে।

### ৬. Core বনাম Distribution: Senior IT Officer-এর কাজের পার্থক্য

| বিষয়         | Core Layer                                          | Distribution Layer                                  |
| ------------- | --------------------------------------------------- | --------------------------------------------------- |
| প্রধান লক্ষ্য | দ্রুত ও নির্ভরযোগ্য backbone connectivity           | Routing policy ও network segmentation               |
| সাধারণ কাজ    | Backbone link, routing health, capacity, redundancy | Inter-VLAN routing, ACL, VLAN gateway               |
| প্রধান সমস্যা | Core link down, route failure, congestion           | ভুল VLAN, ACL block, gateway বা local routing issue |
| কাজের ধরন     | সামগ্রিক নেটওয়ার্ক পরিবহন সচল রাখা                 | বিভিন্ন নেটওয়ার্কের যোগাযোগ ও নিয়ম পরিচালনা       |

বাস্তবে দুটি স্তরের দায়িত্ব কিছুটা overlap করতে পারে। বিশেষ করে ছোট নেটওয়ার্কে একই কর্মকর্তা একাধিক স্তর পরিচালনা করেন।

### শেষ কথা

একজন Core Network Senior IT Officer-এর সাফল্য বোঝা যায় তিনটি বিষয় দিয়ে:

1. Availability: নেটওয়ার্ক কতটা সচল থাকে।
2. Performance: ডেটা কত দ্রুত ও নির্ভরযোগ্যভাবে চলাচল করে।
3. Resilience: কোনো ডিভাইস বা লিংক ব্যর্থ হলেও নেটওয়ার্ক কত দ্রুত স্বাভাবিক কার্যক্রম বজায় রাখতে পারে।

সহজভাবে মনে রাখুন: Distribution Layer নিয়ন্ত্রণ ও পথ নির্ধারণে বেশি মনোযোগ দেয়; Core Layer পুরো নেটওয়ার্কের দ্রুত, নির্ভরযোগ্য পরিবহনব্যবস্থা সচল রাখে।
